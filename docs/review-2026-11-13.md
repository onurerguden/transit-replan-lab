## Scope and architecture

Tracked baseline physical lines (blank/comment lines included): 49 maintained source files / **8,164 lines**; 13 test files / **1,606 lines**; 47 generated data/schema/lock files / **12,582 lines**; 52 documentation/configuration files / **1,383 lines**. Binary assets are excluded. “Maintained” distinguishes editable source from generated artifacts; Git does not prove whether a person or an assistant originally wrote a line. No authorship claim is inferred from line count.

The independent verifier, typed role projections, exact offer IDs, versioned writes and bounded search/model budgets are useful boundaries. The largest maintenance concentration is orchestration (570 lines), storage (511), the experiment runner (441) and intake (426). Main risks are the cross-product of revision/checkpoint/terminal state, evaluation sharing production parsing rules, and a small synthetic linguistic distribution. More agents or more lines would not improve these boundaries.

## Design plan

Use `#000000` canvas, translucent `#141414` panels, `#f5f5f5` text, `#a8b0ab` secondary text, `#61e6a5` rider 1, `#f2d35f` rider 2 and `#ff7474` incident red. Keep bundled DM Sans, tabular times and left alignment. Put event → selected offer → verification reason in a compact summary before paired maps. Give rider 1 a solid ride, rider 2 a long-dashed ride and all walks short dashes; labels 1/2 and written legends carry the same meaning without colour. Glass is limited to the header and primary panels; no decorative gradients or ambient animation.

## Verification and measured results

Implementation was paused when the user requested a review document and action plan. This is a working-tree snapshot, not a completed release. No commit, push or tag was made.

- Six new parametrized regression cases failed on the baseline (four defect classes). After the targeted fixes, `uv run --locked --project backend pytest backend/tests/test_review_regressions.py backend/tests/test_vnext.py -m 'not ollama' -q` passed **11 tests**, deselected one Ollama test, in 7.68 seconds. This is test duration, not API latency.
- Ruff check, Pyright (zero errors/warnings), frontend TypeScript checking under Node 24.21.0, and `git diff --check` passed.
- Terminal-state guards, request-digest checks and margin-aware candidate dominance have targeted passing tests. The execution lock still needs multi-process/crash tests. The immutable-output change still needs rerun/concurrency regression tests.
- The lexicon arm, raw-response fields and v2 data generator are implemented but not measured. No v2 corpus audit or new training was run.
- The dark UI is partial. Its new “Rider 1 evidence” label disagrees with an existing E2E expectation for “Rider A evidence”; mobile, keyboard and visual acceptance remain open.
- Full `make check`, build, E2E, clean installation, CI and Docker acceptance have not been completed on this branch. Local Ollama base/adapter imports succeeded, but no new inference comparison was run.

Historical JSONL recounts: development rules/base/adapter = 66/80, 80/80, 80/80; calibration = 50/60, 55/60, 60/60; locked = 100/120, 120/120, 120/120. The locked set has 60 paired TR/EN groups. The adapter's observed gain is confined to five English calibration paraphrases; no general gain over base is established. Four local data/GGUF hashes match the published training manifest, and the local log records 360 training steps. The 20/60 train–validation overlap still prevents interpreting validation loss as independent generalization.

Next gates, in order: reconcile UI assertions and architecture notes; verify crash/concurrency behavior; prove immutable experiment bundles; audit v2 splits without retraining; measure lexicon/base/adapter under matched runtime settings; finish UI acceptance and clean CI/Docker/real-model checks. Preserve all published artifacts and mark new runs as exploratory until a new blind protocol is frozen.
